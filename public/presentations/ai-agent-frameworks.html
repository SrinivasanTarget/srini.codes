01 · THE CORE DISTINCTION

A call answers. An agent acts.

The difference is not model size or a bigger prompt - it is who owns the control flow.

03 · BEFORE YOU REACH FOR AN AGENT

Do you even need one?

Anthropic's guidance, worth stealing: find the simplest thing that works, and add autonomy only when it earns its keep. Reliability is the goal, not autonomy.

  • Prompt chaining — break the task into ordered LLM steps.
  • Routing — classify input, hand it to a specialist path.
  • Parallelization — split work, or vote across attempts.
  • Orchestrator-workers — a lead splits, delegates, then synthesizes.
  • Evaluator-optimizer — a judge scores, a generator revises, loop.
⚑

Most production systems are a workflow with clear steps - not an autonomous agent. Try these five patterns before you hand the model the keys.

06 · THE INTEROPERABILITY LAYER

The standards the tour skips.

2026 is the year these converge. Three acronyms, and the wiring diagram falls into place: tools, other agents, and the call underneath both.

🔌

MCP

Model Context Protocol — agent-to-tools. The agent says what it needs; a server handles how. Framework-agnostic: one server serves LangGraph, CrewAI, or Claude alike.

→ Anthropic · open standard
🔗

A2A

Agent-to-Agent — agent-to-agent. Lets a CrewAI agent and a LangGraph agent discover and delegate to each other across frameworks. ADK supports it natively.

→ Google · 150+ orgs
{}

Function calling

The primitive underneath both. The model emits a structured call against a typed schema; your runtime executes it and feeds the result back.

→ Every major model

08 · VOCABULARY THAT OUTLASTS FRAMEWORKS

Design patterns.

Frameworks come and go; these compose the same way in any of them. Teach the patterns and the tool choice becomes an implementation detail.

base loop 🔄

ReAct

Interleave reasoning and acting - think, call a tool, observe, repeat. The canonical single-agent loop.

self-correction 👀

Reflection

The agent critiques its own output against a rubric and revises. A cheap quality lift.

decompose 📋

Planning

Break a goal into ordered sub-steps before acting - keeps long tasks on the rails.

delegate 🏗

Orchestrator-workers

A lead LLM splits the task, delegates to workers in parallel, and synthesizes results.

doer + judge ⚖

Evaluator-optimizer

A generator produces, a judge scores against criteria, loop until it passes.

fan-out 🔁

Routing & parallelization

Classify and send to a specialist, or split work and vote across attempts.

09 · WHAT DEMOS HIDE, PRODUCTION SHOWS

Cost, and observability.

Autonomy has a bill. Every loop is another call, and traditional monitoring cannot see whether the answer was right - only that one came back.

Trace, do not just log

Same input can yield different tool paths. You need the full step-by-step - LangSmith, OpenTelemetry, Langfuse - to debug decisions.

✨

Eval on a sample

Score sampled traffic with an LLM-as-judge against rubrics. Turn real failures into a regression dataset.

🛡

New attack surface

Prompt injection: direct, indirect (poisoned docs), chained agent-to-agent. Alert when one tool is called 10+ times.

10 · THE DEBATE, RECONCILED

One agent, or many?

Two famous posts with opposite titles are actually saying the same thing. It is a decision about the shape of the task, not a religion.

Anthropic · multi-agent research
+90.2% over single-agent

A lead plus parallel subagents won big on their research eval - because the work was parallelizable, exploratory reads.

Cognition · don't build multi-agents
Single-threaded wins

Parallel agents fragment decisions and lose each other's context - bad for sequential, state-dependent writes.

⚖

The rule: multi-agent for parallel reads and exploration; a single linear agent for sequential writes and coherence. Reliable context-passing between agents is still unsolved - so single-threaded is the safer default.
